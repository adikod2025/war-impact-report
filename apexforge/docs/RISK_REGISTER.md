# Risk Register

Derived from the IntelliSwarm validation (Roadmap §5), the residual risks in the
Final Dev Handoff §1.1, and risks discovered during the Layer 1 build.

Status values: **OPEN** (unmitigated), **MITIGATED** (control in place, residual
accepted), **CLOSED** (no longer applicable).

## Discovered during the Layer 1 build

| ID | Risk | Mitigation | Owner | Status |
|---|---|---|---|---|
| R-09 | The handoff defines `SwarmLevel` twice and `FleetRegistry`/`Asset` twice, in different modules, with subtly different shapes — the exact drift Pitfall 1 describes, present in the source material itself. | Both are defined **once** in `apexforge/contracts/` and re-exported from the modules whose published import paths the handoff's tests use. Documented in `docs/CONTRACTS.md`. | Architecture | MITIGATED |
| R-10 | Assurance staleness computed from wall-clock time would misfire under NTP correction or clock step, silently converting fresh evidence to UNKNOWN (or worse, stale evidence to fresh). | `PlatformVerdict` carries a monotonic timestamp and the fabric ages evidence from it. Wall-clock ISO time is retained for audit only. | Assurance | MITIGATED |
| R-11 | Development-grade HMAC policy signing is not a hardware root of trust. An attacker with filesystem access can re-sign a tampered policy. | Accepted for Layer 1. The *interface* (sign / verify / refuse to load unverified) is fixed now so Layer 6 swaps in measured boot and a hardware root of trust without changing call sites. Signing key is overridable via `APEXFORGE_POLICY_KEY` and the committed default is explicitly marked not-for-production. | Assurance | OPEN |
| R-12 | Latency measured on x86-64 CI hardware may be reported as if it were a target-platform figure, recreating Pitfall 8 in the reporting rather than the code. | `docs/EDGE_PROFILE.md` states the scope of every latency claim; the performance test names the machine class in its output. | Edge lead | MITIGATED |
| R-13 | Layers 3–6 are documented but not implemented. A reader skimming the repository could mistake interface stubs for delivered capability. | Every deferred item is marked in `DEV_CYCLE_MEMORY.md`, `docs/ACCEPTED_LAYER.md` and the module docstrings. No stub claims to be a model, a bearer or a deployment. | Tech lead | MITIGATED |
| R-14 | The in-process mesh proves eventual consistency under a *modelled* loss process, not a real contested RF environment. | Stated plainly in `docs/design-notes/mesh.md`. Layer 2 exit requires the production bearer. | Mesh lead | OPEN |

| R-15 | **The handoff's own `decide()` ordering checks the track branch before the RTB battery threshold**, so a platform holding a target continues tracking below its return-to-base margin. Reproduced faithfully rather than silently changed — altering autonomy behaviour unilaterally is what ADR-001 forbids. | Documented as limitation #1 in `docs/design-notes/edge-agent.md` and surfaced here. **Requires a product/safety decision before Layer 2 exit**: either accept custody priority explicitly, or raise an ADR to reorder the branches. Not a code fix an agent may make alone. | Product + Edge lead | OPEN |
| R-16 | Distinct human decision points originally shared three policy gates, so mission approval, authority acceptance, OTA rollout and degraded continuation could not carry distinct timeouts or escalation targets — the Pitfall 4 failure at the policy layer rather than the code layer. | Closed in Policy Package v1.1.0: seven additional gates declared, each with its own notify/timeout/escalation, and the catalog rewired to them. `POLICY_GATES` is now derived from the signed package rather than hard-coded, so the two cannot drift again. | Assurance | MITIGATED |
| R-17 | **The DDIL mesh wraps payloads in an envelope; the mock does not.** A consumer reading `msg["role"]` worked against the mock and silently returned `None` against the mesh, so decentralized role negotiation stopped deconflicting with no error anywhere — two platforms both taking the same track. Found at integration, not by any module's own suite. | Envelope shape pinned in `contracts/transport.py` with `ENVELOPE_KEYS` and `unwrap_payload()`; the EdgeAgent's `peer_roles()` normalises through it; regression test `test_role_negotiation_deconflicts_over_the_real_ddil_mesh` proves deconfliction over the real bearer. | Architecture | MITIGATED |
| R-18 | `EdgeAgent` exposed only `platform_id`, while the handoff's published interface and its own integration smoke test use `agent.id`. The published import path would have broken for any consumer following the handoff. | `id` restored as a property that always agrees with `platform_id`; both names live. Caught by WF-SMOKE-01 on its first run, which is the argument for keeping that test verbatim. | Architecture | MITIGATED |
| R-19 | Two classes named `MeshPeer` exist — the mock in `edge_agent.core` and the bearer-backed adapter in `mesh.ddil`. Signature-compatible today, but one name for two classes across packages is the drift the ICD exists to prevent. | Tolerated for Layer 1 because the mock is what makes the published unit tests runnable without a network. Retire the mock when the EdgeAgent defaults to the real bearer (Layer 2 exit). | Mesh lead | OPEN |
| R-20 | Latency figures are measured on an x86-64 CI host. `tests/test_performance.py` prints the host class with every measurement and the assertion margins are deliberately generous, so the gate is a regression detector, not a platform qualification. | Superseded operationally by R-02; retained here so the reporting limitation is not lost when R-02 is closed. | Edge lead | OPEN |

| R-21 | **Custody duplication does not recover after a network partition heals.** During a blackout every platform independently takes `track` — correct, since nobody can deconflict blind. But `decide()` evaluates `peer_owns_track` only when the prior role is not already `track` (`apexforge/edge_agent/core.py`), so when the link returns none of them relinquish and multiple simultaneous trackers persist to mission end. Found by the DDIL simulation scenario, not by any unit test — the "re-role logic that never ran in anger" symptom Pitfall 2 predicts. | **Not fixed in this baseline.** Changing autonomy behaviour unilaterally is what ADR-001 forbids, and a relinquish rule is a real design decision, not a bug fix. Recommended: a deterministic tie-break (e.g. lowest platform id retains custody, others re-role on the first post-partition role advertisement), specified in an ADR and added to WF-03/WF-06 before Layer 2 exit. `tests/test_sim.py` reproduces it deterministically, so the fix will have a ready regression test. | Product + Edge lead | OPEN |

## Found by the adversarial verification swarm (P4)

Three auditors were run against the finished, green, 98.9%-covered build. They
found holes that 902 passing tests did not. Every one is recorded here whether
or not it was fixed, because the pattern matters more than the individual bugs:
**the tests asserted the literals the controls already named, rather than the
properties the ADR claimed.**

| ID | Risk | Mitigation | Owner | Status |
|---|---|---|---|---|
| R-22 | **The committed baseline shipped a bypassable version of its own headline invariant.** `MacroAction` enforced sparsity with a top-level *denylist*. Keys nobody thought of (`route`, `path`, `nav`, `goto`, `course`, `bearing_deg`, `loiter_point`, `pointing`, `look_at`) passed untouched, and because the Orchestrator copies `Objective.area` verbatim into every macro-action, the *named* keys worked one level down: a stock `assign()` put `heading`, `gimbal` and even `weapon` on the wire. ADR-001, `docs/design-notes/orchestrator.md` and `README.md` all asserted this was structurally impossible. | **Fixed.** `MacroAction.params` and `params["area"]` are now allowlists (`ALLOWED_PARAM_KEYS`, `ALLOWED_AREA_KEYS`), and forbidden terms are scanned at every depth (`_forbidden_at_any_depth`, depth-bounded). Regression tests assert the *property* — arbitrary unlisted keys, nested keys, and the end-to-end laundering path through `Objective.area`. ADR-001's enforcement table corrected. **Recorded rather than quietly patched: the fact that this shipped is the finding.** | Architecture | MITIGATED |
| R-23 | A duck-typed object with `approved = True` satisfied `WorkflowEvent.human_approved`, because the mandatory `operator_id` and `rationale` live in `HumanDecision.__post_init__` — which a stand-in never reaches. An anonymous approval could be written into the immutable audit trail. | **Fixed.** `human_approved` is `isinstance`-checked. The workflow engine now rejects a non-genuine decision as `human_decision_rejected` and keeps the gate open, rather than recording it as a human *denial* — a decision no person made must not appear in the audit trail at all. | Assurance | MITIGATED |
| R-24 | The Orchestrator's human gate minted its correlation id *internally*, so no `HumanDecision` could ever reference it and the binding check was unsatisfiable. Any approving decision — a maintenance approval for a different airframe on a different day — authorised an over-limit tracking assignment, and replayed indefinitely. | **Fixed.** The correlation id now comes *from* the decision; the decision must also name the gate (`step_id`); and each decision is single-use (`_consumed_decisions`). Authority is granted once, for one dispatch. | Assurance | MITIGATED |
| R-25 | `WorkOrderBridge.submit()` admitted a hand-built order with `state="approved"` and a decision stolen from a different work order, and admitted an order whose recommendation had been mutated *after* approval — forwarding an operator's name to an action they never saw. The design note claimed both were refused. | **Fixed.** `is_approved` now requires the decision to name this order and this gate, and compares a fingerprint of the recommendation taken at approval time. Approval is consent to a specific action on a specific platform. | Assurance | MITIGATED |
| R-26 | The LOI ceiling was clamped once in `__init__` and read from an instance attribute thereafter, so `self.max_loi = 5` after construction sent LOI-4 and LOI-5 messages to the vehicle. | **Fixed.** The ceiling is re-derived against `ACCEPTED_LAYER_MAX_LOI` on every check. The hard cap belongs to the accepted Layer, not to an object's state. | Mesh lead | MITIGATED |
| R-27 | An injected clock stepping backwards made stale evidence look fresh and re-admitted it as PASS — the optimistic reading of a bad clock, which is the dangerous one. | **Fixed.** A negative age is treated as a clock fault and ages the verdict out. Latent rather than live (the default is `time.monotonic`), but fixed at the boundary. | Assurance | MITIGATED |
| R-28 | `emit_event()` let a caller supply its own `timestamp` or `schema_version`, so an audit entry could be backdated or mislabelled; whitespace-only actor values satisfied the attribution check. | **Fixed.** Both are refused, loudly rather than silently, so the attempt is visible. | Platform | MITIGATED |
| R-29 | **`RuntimeAssuranceFabric.validate_actions()` — the pre-execution half of the Assurance Layer, and the concrete implementation of ADR-001's "compositional verification of every macro-action" — has no production caller.** The only live Intent→Execution gate is the Orchestrator's own single-rule check. `KnownRoleRule`, `NoDuplicateAssignmentRule` and `PolicyVersionRule` never run against a real dispatch, and the fabric cannot currently be injected into the Workflow Engine (it exposes no `check_step`). "No layer bypasses the Fabric" holds partly because little goes through it. | **Not fixed.** Wiring the fabric's rule set into the Orchestrator's dispatch path is a real architectural change affecting every assignment, and belongs in an ADR with the Layer 2 exit rather than in an unreviewed edit at the end of a build. The behaviour today is fail-safe in direction (the Orchestrator's own gate still blocks over-limit plans) but the assurance surface is far thinner than the ADR implies. **This is the most significant open item in this baseline.** | Architecture + Assurance | OPEN |
| R-30 | `MacroAction.requires_human_approval` is set and logged but has no consumer that changes behaviour, and the sim harness applies the role identically whether it is set or not. | Not fixed. Depends on R-29: the flag's natural consumer is the pre-execution assurance path that does not yet run. | Architecture | OPEN |
| R-31 | Mesh peer role advertisements are unauthenticated, so a spoofed peer claiming `role="track"` strips custody from a real platform. Outside the eight ADR-001 invariants, but squarely a property of the bearer. | Not fixed. Belongs with the production bearer in Layer 2, where peer identity and message authentication are part of the transport's job. | Mesh lead | OPEN |
| R-32 | Three design notes described code that integration had already changed, and `DEV_CYCLE_MEMORY.md` claimed the audit log was "append-only by construction" while `AuditLog.clear()` exists. Pitfall 7's named symptom — "design notes that no longer match the code" — appearing in the repository that appoints itself to police it. | **Fixed.** All four claims corrected. The lesson is that a design note written mid-build goes stale at integration; the fix is to re-read them at the exit gate, which is now an explicit step in the gate checklist. | Tech lead | MITIGATED |

| R-33 | **The CI workflow had never run and could not run.** `ci.yml` sat at `apexforge/.github/workflows/`; GitHub Actions discovers workflows only at the repository root. Every gate it advertised — policy signature, contract tests, WF-SMOKE-01, invariants, coverage, perf, sim, the 3.10–3.12 matrix — was decorative. `CLAUDE.md`'s promise that "CI must fail if WF-SMOKE-01 goes red" was untrue, and it is why the tree could sit red for fifteen minutes during the audit with nothing noticing. | **Fixed.** `git mv apexforge/.github .github`. The workflow's contents were already correct for that layout (`working-directory: apexforge`, `paths: ["apexforge/**"]`). **Residual: it still has not executed once**, so the Python 3.10/3.12 legs remain unproven — and with `filterwarnings = ["error"]`, a version-specific `DeprecationWarning` is a realistic cross-version breaker. First push is the real test. | DevOps | MITIGATED (residual open) |
| R-34 | **The `emit_event` bypass detector was close to cosmetic.** It matched only a bare `ast.Name` receiver from a three-name allowlist — excluding `_LOGGER` (the actual module logger in `workflows/engine.py`), `self.logger`, and `logging.getLogger(...).info(...)`. A raw log on the act path left `-m invariant` fully green; it was caught only by accident, by an unrelated test that parses emitted JSON. `CLAUDE.md` makes a specific promise about this test that was not kept. | **Fixed.** The detector now resolves attribute and call receivers, matches any logger-ish name, and watches a wider set of high-consequence functions. A guard-the-guard test asserts it catches all four spellings and does not fire on `emit_event` or on unwatched functions. Verified by planting the exact bypass in `EdgeAgent.act()`: previously green, now fails. | Platform | MITIGATED |
| R-35 | `--cov-fail-under=80` against ~99% actual coverage left roughly 650 statements of slack. Someone could delete that much test reach and CI would still pass — a threshold well below reality cannot detect a regression. | **Fixed.** Ratcheted to 97 in both `verify.sh` and `ci.yml`. | Tech lead | MITIGATED |
| R-36 | The suite only ran one way. `apexforge` was never installed, so imports resolved solely because `python3 -m` puts the cwd on `sys.path`; bare `pytest tests/...` failed, and the README's documented `pip install -e ".[test]"` path was never exercised. | **Fixed.** `pythonpath = ["."]` declared in `pyproject.toml`, so the documented invocation and the one people actually type are the same path. | Tech lead | MITIGATED |
| R-37 | No test-order randomisation exists anywhere (`pytest-randomly` absent, no shuffling in `addopts`), so `-p no:randomly` is a silent no-op. Manual shuffling during the audit found no order dependence, but nothing in CI would catch one introduced later. `tests/test_sim.py` also seeded the global RNG and left it mutated. | RNG leak **fixed** (state saved and restored). Adding `pytest-randomly` is **not fixed** — it is a new dependency and belongs in a reviewed change rather than a late edit. | Test lead | OPEN |

## Review

The register is reviewed at every Layer Exit Review. An OPEN risk carried into a
new Layer requires either a mitigation plan with a date or a written residual-risk
acceptance from a named owner.
